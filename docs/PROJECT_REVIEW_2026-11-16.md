# 전체 점검 — 2026-11-16

## 점검 범위와 결론

현재 작업 폴더의 Python 코드, 웹 화면 HTML/CSS/JavaScript, 실행 배치 파일, 배포 목록, 테스트, 기존 결과물과 문서를 확인했다. 브라우저 화면을 직접 조작하는 시각 검사는 수행하지 않았다. 코드 수정은 하지 않았다.

PDF 생성·QR 배치·접속 기록이라는 핵심 기능은 작동한다. 실제 OCR/생성형 AI에 대한 방해 효과는 아직 측정되지 않았다. 기능 검증 결과를 부정행위 방지 성능으로 해석하면 안 된다.

## 작업본과 실행 환경

- 최상위 폴더에는 `.git`이 없지만 `.github-publish` 안에 Git 저장소가 있다.
- 해당 저장소의 원격은 `https://github.com/JM-KIMM/watermark_ai.git`, 로컬 브랜치는 `main`, 마지막 로컬 커밋은 `73ba2bc`다.
- `.github-publish`의 추적 파일과 최상위 대응 파일의 해시를 비교했으며 차이가 없었다. Git 작업 트리도 깨끗하다.
- GitHub 연결 도구의 원격 조회는 404였다. 원격 최신 커밋과 같다는 의미는 아니다.
- 시스템 `python`은 WindowsApps 실행 별칭으로 정상 실행되지 않았다. `py -3.12`로 설치된 Python을 확인했다.
- 점검을 위해 프로젝트 `.venv`를 만들고 `requirements-dev.txt`의 의존성을 설치했다. 실행 환경은 PyMuPDF 1.28.2, qrcode 8.2, Pillow 13.0.0, OpenCV 4.14.0.94, NumPy 2.5.4다.

## 기능 구조

| 구성 | 역할 |
|---|---|
| `webapp.py`, `web/` | 로컬 웹앱. 파일 선택, 강도 설정, 생성 진행, 첫 페이지 미리보기, PDF/설정/CSV 다운로드 |
| `watermark.py` | 공통 PDF 생성 엔진. 테두리, 대표 문장 추출, 글자 크기·가로 비율 변동, 결과 기록 |
| `question_marks.py` | 문제 번호 감지, 본문과 겹치지 않는 QR 위치 탐색, 선택적 번호 무늬 |
| `source_glyphs.py` | 원본 본문 글자 이미지를 추출해 테두리에 재사용 |
| `line_patterns.py` | 3단계에서 고립된 긴 구분선을 QR 유래 무늬로 변경 |
| `csv_store.py` | 현재 CSV 저장소. 파일 잠금, 보관 기간, 수식 이스케이프, 발급·접속·사건 관리 |
| `tracking_db.py` | QR 접수 HTTP 서버, 요청 제한, 저장소 선택. 이전 SQLite 구현도 남아 있음 |
| `app.py`, `db_manager.py` | 별도 Tkinter 생성 화면과 기록 관리 화면 |
| `migrate_legacy.py` | 기존 SQLite를 읽기 전용으로 열어 CSV로 이관 |
| `package_web.py` | 명시된 파일만 배포 ZIP에 포함 |

웹 생성은 25MB·100쪽, 동시 작업 1개, 작업당 15분, 실행당 제출 20회로 제한한다. 1단계는 문제별 QR, 2단계는 QR과 테두리, 3단계는 구분선 변경까지 수행한다. 스캔 PDF의 OCR과 LLM 연동은 없다. QR 기록은 웹 화면에서 기본 비활성이다.

## 검증 결과

1. `.venv/Scripts/python.exe -m unittest discover -v`: **18개 모두 통과**.
   - PDF 업로드부터 생성·다운로드까지 실제 로컬 HTTP 왕복
   - 로컬 토큰·출처 검사
   - 강도 1·2·3, 테두리 배치, 본문·그래프 보존
   - 난수 시드 재현과 글자 크기·가로 비율 범위
   - CSV 동시 쓰기, 기록 상한·만료, 이관, 내보내기
   - IP 헤더 위조 무시, 접근 시간, 요청·동시 연결 제한, 저장 장애 복구
2. `verify.py`를 그대로 실행하면 이전 PC의 절대 경로 때문에 실패한다.
3. 원본 파일 12개 묶음의 SHA-256이 기존 manifest와 일치함을 확인했다. manifest 복사본을 임시 폴더에 만들고 경로만 현재 위치로 바꿔 기존 검증기를 실행했다. **60쪽 본문 렌더링 검증 통과**.
4. 같은 방식으로 QR 검증기를 실행했다. **QR 100개가 150dpi와 300dpi에서 각각 100/100 복원**됐다. 문제 감지 118개 중 14개는 공간 부족으로 QR이 생략됐다. 이 수치는 QR 영역을 잘라낸 디지털 이미지 검사다.
5. 배포 목록의 파일은 모두 존재한다. 기존 배포 ZIP은 덮어쓰지 않았다.

기존 원본 시험지·결과 PDF·manifest·QR 통계·접속 기록은 변경하지 않았다. 검증 보정은 임시 파일에만 적용했다.

## 확인한 문제와 우선순위

### 1. 회전 PDF의 표시 방향 보존 — 우선 수정

위치: `watermark.py:252` 부근.

본문을 새 페이지에 `show_pdf_page()`로 가져올 때 원본 페이지의 회전과 대상 좌표를 처리하지 않는다. 같은 문서를 0·90·180·270도로 설정해 생성한 결과에서 출력 첫 단어와 QR 좌표가 모두 동일했다. 90·270도에서는 캔버스 크기만 바뀌고 본문 배치가 원래 회전 표시와 달라진다. 기존 테스트는 회전 없는 PDF만 검증한다.

수정 방향: 본문과 QR·번호·구분선에 같은 좌표 변환을 적용하고 네 방향에 대해 원본 표시 결과와 비교한다.

### 2. 주석·링크 누락 — 입력 보존 범위 결정 필요

위치: `watermark.py:254`.

링크 1개와 메모 주석 1개를 넣은 합성 PDF로 재현했다. 결과 PDF에는 둘 다 0개였다. 본문 페이지를 가져오는 현재 방식은 이런 요소를 별도로 복사하지 않는다. 주석으로 추가한 내용이 있는 시험지는 출력에서 내용이 빠질 수 있다.

수정 방향: 주석을 출력에 반영하거나 필요한 요소를 복사한다. 지원하지 않을 경우 생성 전에 감지해서 사용자에게 알린다.

### 3. 업로드 원본·결과의 보관 정책 없음

위치: `webapp.py:107–110`, `webapp.py:192`.

업로드 원본을 `outputs/web/<작업ID>/source.pdf`에 저장하며, 종료 시에는 프로세스만 정리한다. 원본·결과 파일의 자동 정리나 화면 내 삭제 기능은 없다. 실행당 20회 제한은 재시작으로 초기화되므로 디스크 누적 상한이 아니다. CSV 보관 기간 설정은 시험지 파일에는 적용되지 않는다.

수정 방향: 원본 삭제 시점과 결과 보관 기간을 정하고, 실패한 작업과 오래된 파일을 정리한다.

### 4. 기존 검증기가 PC 이동 후 실행되지 않음

위치: `verify.py:18–20`, `verify_question_marks.py:25` 부근.

manifest의 절대 경로를 그대로 사용한다. 실제 파일과 해시는 정상인데 이전 사용자 폴더를 찾다가 중단됐다. 이번 점검에서는 임시 경로 보정으로 검증했지만 프로젝트 자체는 아직 수정하지 않았다.

수정 방향: 프로젝트 기준 상대 경로나 입력·출력 루트 재지정 옵션을 지원한다.

### 5. 기존 데스크톱 실행 파일의 Python 탐색 실패

위치: `실행.bat:3`.

`python app.py`만 호출하므로 현재 PC에서는 정상 시작할 수 없다. `웹실행.bat`은 `py -3`와 `.venv`를 사용하므로 이 문제를 피한다. 데스크톱 화면은 QR 기록도 기본 활성이라 웹 화면과 기본값이 다르다(`app.py:31`).

수정 방향: 실행 환경 선택을 통일하고 웹·데스크톱의 지원 범위와 기본값을 명확히 한다.

## 추가 설계 검토 사항

- CSV 파일별 교체는 원자적이지만 여러 표를 한꺼번에 바꾸는 작업 전체는 원자적이지 않다(`csv_store.py:118–136`). 중간 파일 교체 실패나 프로세스 종료에 대한 복구 방식이 필요하다. 이번 점검에서는 장애 시 여러 표가 동시에 복구되는 시나리오까지 검증하지 않았다.
- 문제 감지는 `N.`과 `【문제N】` 중심이다. 다른 번호 형식, 소문항, 스캔 입력을 모두 지원하는 상태가 아니다.
- `source` 모드는 원본 글꼴 파일을 복제하는 방식이 아니라 글자 이미지 재사용이다. 일부 글자는 대체 글꼴로 나온다.
- 본문 확대/축소 없는 테두리는 페이지 자체를 크게 만든다. 실제 인쇄 시 용지 맞춤 축소와 가독성 검사가 필요하다.
- 요청 제한·Host/Origin 검사·토큰 보호 등은 구현돼 있다. 이번 점검은 완전한 보안 감사나 외부 배포 부하 시험은 아니다.
- AI 방해 효과를 확인하려면 원본 대비 OCR 오류율, 문제 풀이 정답률, 촬영·크롭 조건, 사람의 읽기·필기 시간을 별도로 측정해야 한다. `experiment_plan.csv`는 계획이며 실측 결과가 아니다.
